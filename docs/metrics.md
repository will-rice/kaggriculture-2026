# Toad phase 1 — metric reference

One row per key `toad._record` logs, grouped the way wandb groups the
dashboard: the text before the first `/` is the section. Every run also ships
this table into the logger config as `metric_definitions` (see
`toad.build_wandb_logger`), so the meaning of a number sits beside the number
instead of requiring a source read.

The last column is the one this project keeps needing and the one that would
have caught [the 2026-08-21 incident](#the-incident): a reader trusted two
metrics because their curves went the right direction, when the correct
reading was already sitting in a source comment. "What it measures" restates
the metric; "if false" says what the same curve looks like when the belief it
is being read as evidence for is actually wrong.

## The incident

On 2026-08-21 a reader looked at a live run's dashboard and concluded it was
going well, off two metrics that were both misleading:

- `win_rate_mirror` (now `diag/mirror_decisive_rate`) rose 0.25 → 0.50 and
  read as progress. It is 0.5 by construction in its raw form — self-play
  records both seats and one wins, ties score as losses — so it rose only
  because the policy stopped tying with itself, then pinned at its ceiling for
  300+ updates.
- `reward_mean` (now `proxy/shaped_reward_mean`) rose 2.5× while
  `margin_mean_vs_econ` (now `objective/margin_vs_econ`) stayed flat at about
  −140,000 and `win_rate_vs_econ` (now `objective/win_rate_vs_econ`) stayed
  **0.000 for all 893 logged rows**. About three-quarters of the shaped
  reward is shaping credit, not coins.

## objective/ — what we actually want

| Metric                       | What it measures                                                                                                                                                  | Range / structural ceiling                                                                    | What it would look like if the thing you believe were false                                                                                                                                                                                                                            |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `objective/win_rate_vs_econ` | Fraction of games against the scripted opponent (`economic_policy`) with `final_margin > 0` — the competition's own statement of the win condition, undecomposed. | `[0, 1]`, no structural ceiling; `1.0` means genuinely winning every game.                    | Stays 0.000 across hundreds of updates while every `proxy/` and `diag/` metric rises — exactly what happened for 893 rows in the incident. If capability were actually improving, this has to move eventually; if it never does, nothing else on the dashboard is evidence that it is. |
| `objective/margin_vs_econ`   | Mean `final_margin` (our terminal bank minus the scripted opponent's) against `economic_policy`.                                                                  | Unbounded in principle, in the tens of thousands of coins in practice; no structural ceiling. | Stays deeply negative and flat (observed ~−140,000, unchanged to 4 s.f. across 500 updates in one arm) while `objective/win_rate_vs_econ` and every proxy/diag metric move — the policy has not closed the gap the competition actually scores.                                        |

## proxy/ — what the gradient reads

| Metric                     | What it measures                                                                                                                                        | Range / structural ceiling                                                                                                                                                                                   | What it would look like if the thing you believe were false                                                                                                                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `proxy/shaped_reward_mean` | Episode total of whichever reward series (`REWARD_FIELD`, or `--no-money` / `--margin` / `--own` / `--sparse`) this arm's gradient actually trains on.  | No fixed ceiling — a training statistic, not a score. Toad's shaped series runs through a `/500` normaliser with a 10x terminal result riding in from turn one, so its scale is arbitrary relative to coins. | Rises steadily (measured 2.5×, 0.06 → 0.15) while `objective/margin_vs_econ` and `objective/win_rate_vs_econ` stay flat — the rise is shaping credit (about three-quarters of it, measured), not improved play. This is the second half of the incident.     |
| `proxy/shaped_mean`        | Episode total of Toad's shaped reward specifically, logged unconditionally on every arm regardless of what the gradient actually trains on.             | Same caveat as `proxy/shaped_reward_mean`; not comparable across arms with a different `REWARD_FIELD`.                                                                                                       | On a `--no-money` or margin arm, tracks `proxy/shaped_reward_mean` in lockstep — would mean the "counterfactual" series is secretly identical to the trained one, so the ablation is not testing what it claims to.                                          |
| `proxy/money_term`         | The money component's own realised contribution to the shaped reward (`shaped_money - shaped`), separable because both series ride on every trajectory. | Signed, so a round trip that loses coins loses reward; the clamp that made it help-only was deleted.                                                                                                         | Rises alongside `diag/gross_purchases` while `diag/bank_mean` stays flat or falls — the money-pump signature. The delta is signed now, so this watches for the clamp coming back rather than for the pump it once paid for. Hit three times on this project. |

## critic/ — value-head diagnostics

| Metric                                    | What it measures                                                                                                                                                                                                            | Range / structural ceiling                                                                                                                                 | What it would look like if the thing you believe were false                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `critic/baseline_self_consistency`        | Value loss against the round's own bootstrapped TD(λ) target — how well the critic predicts a target built partly from its own earlier outputs.                                                                             | `>= 0`, falls toward 0 as the critic fits its own target more closely; no floor tied to the real return.                                                   | Falls steadily while `critic/ev_econ_games` stays negative or falls — the critic is fitting a moving, self-referential target rather than learning to predict the real outcome. Measured: a critic sat at 0.998 explained variance against its own target while explaining the real return twelvefold _worse_ than a constant; ten earlier arms read the fall as "the critic is learning." |
| `critic/baseline_passes_self_consistency` | The same self-consistency loss, averaged over the extra `--value-passes` replays (equal to `critic/baseline_self_consistency` when there are none).                                                                         | Same as `critic/baseline_self_consistency`.                                                                                                                | Same as `critic/baseline_self_consistency`; additionally, an arm run with `--value-passes > 0` where this exactly equals `critic/baseline_self_consistency` means the extra passes never ran.                                                                                                                                                                                              |
| `critic/ev_econ_games`                    | Pooled explained variance, `1 - Var(return - value) / Var(return)`, of the actor's value estimates against the real discounted return-to-go, scripted-opponent seats.                                                       | `<= 1`, can be very negative; a critic that has learned only the turn clock scores ~0.98 without discriminating any two episodes.                          | Sits near 1.0 while `critic/ev_within_turn_econ_games` sits at or below 0 — the apparent accuracy is entirely the deterministic turn-index profile of the return, not anything learned about the state.                                                                                                                                                                                    |
| `critic/ev_within_turn_econ_games`        | The same explained variance after centring both series at each turn index, so the deterministic calendar component cancels and what is left is whether the critic tells two episodes apart at the same point in the season. | `<= 1`; `0` or below means no better than the cross-episode mean at that turn.                                                                             | Stays negative for hundreds of updates while `critic/baseline_self_consistency` falls — the critic is not learning to predict the real outcome even though its self-consistency loss looks good. Measured: predicted-over-actual ratio rising from 1.95 to 8.91 across a season while explaining the return worse than a constant.                                                         |
| `critic/ev_mirror_games`                  | Same as `critic/ev_econ_games`, self-play seats.                                                                                                                                                                            | Same, but a mirror seat's return is very nearly deterministic (both sides are the same policy), so this runs high for reasons unrelated to critic quality. | Runs high (near 1.0) even off a freshly initialised, untrained critic — would confirm this is inflated by self-play's near-determinism rather than by anything learned, which is why it is never compared directly to `critic/ev_econ_games`.                                                                                                                                              |
| `critic/ev_within_turn_mirror_games`      | Same as `critic/ev_within_turn_econ_games`, self-play seats.                                                                                                                                                                | Same non-comparability caveat as `critic/ev_mirror_games`.                                                                                                 | Same as `critic/ev_mirror_games`.                                                                                                                                                                                                                                                                                                                                                          |

## diag/ — cannot indicate capability on its own

| Metric                         | What it measures                                                                                                                                                                                 | Range / structural ceiling                                                                                                                                                                                | What it would look like if the thing you believe were false                                                                                                                                                                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `diag/update`                  | Optimizer rounds completed.                                                                                                                                                                      | Nonnegative int, +1 per logged row.                                                                                                                                                                       | Repeats or resets without a `--resume` — the checkpoint/resume path replayed history instead of continuing it.                                                                                                                                                                                               |
| `diag/steps`                   | Environment decisions collected so far (mirror seats count double).                                                                                                                              | Nonnegative int, increasing by `_seats_per_update(econ_fraction) * TURNS` per update.                                                                                                                     | Grows slower than the update count predicts — collection stalling or a worker dying silently.                                                                                                                                                                                                                |
| `diag/hours`                   | Wall-clock hours since the run started.                                                                                                                                                          | Nonnegative float, increasing.                                                                                                                                                                            | Stops advancing while `diag/update` keeps climbing — a clock or logging bug, not a training signal.                                                                                                                                                                                                          |
| `diag/lr`                      | Current learning rate off the `LambdaLR` schedule.                                                                                                                                               | `[MIN_LR_MOD * LEARNING_RATE, LEARNING_RATE]`, monotonically non-increasing.                                                                                                                              | Rises, fails to reach the floor by `TOTAL_STEPS`, or jumps discontinuously across a `--resume` — `_decay`'s update-count math (keyed on `econ_fraction`) is wrong for this arm, silently changing the recipe mid-run.                                                                                        |
| `diag/warming`                 | Whether the value head is training alone (`--value-warmup`), before the policy gradient fires.                                                                                                   | Bool.                                                                                                                                                                                                     | True for the whole run, or false from update 1 on an arm that passed `--value-warmup` — the warmup budget never consumed or never started.                                                                                                                                                                   |
| `diag/warmup_left`             | Batches still owed to that warmup.                                                                                                                                                               | Nonnegative int, counts down to 0.                                                                                                                                                                        | Goes negative, or stalls while `diag/warming` is still true — the Lightning warmup countdown is broken.                                                                                                                                                                                                      |
| `diag/n_econ_envs`             | Scripted-opponent trajectories collected this round.                                                                                                                                             | `[0, ENVIRONMENTS]`, fixed by `--econ-fraction`.                                                                                                                                                          | Drifts from `int(ENVIRONMENTS * econ_fraction)` — the typed round allocation is wrong.                                                                                                                                                                                                                       |
| `diag/bank_mean`               | Mean terminal bank, both populations pooled.                                                                                                                                                     | `>= 0` in practice, no fixed ceiling.                                                                                                                                                                     | Rises steadily while `objective/win_rate_vs_econ` stays at 0.000 — corpus mining over 1,350 seats put bank against ladder rating at Pearson −0.043, so a bank rise alone is not evidence of anything competitive.                                                                                            |
| `diag/bank_max`                | Max terminal bank, both populations pooled.                                                                                                                                                      | Same as `diag/bank_mean`, more volatile (single best episode).                                                                                                                                            | Same as `diag/bank_mean`; if this rises while `diag/bank_mean` stays flat, it is one lucky episode, not a shifted distribution.                                                                                                                                                                              |
| `diag/bank_mirror`             | Mean terminal bank, self-play seats only.                                                                                                                                                        | Same as `diag/bank_mean`.                                                                                                                                                                                 | Rises sharply above `diag/bank_vs_econ` and the gap widens for 200+ updates — the conflation that made one arm (C'') read as capability for 209 updates while self-playing at ~50 and banking 8 against the scripted opponent. The two populations must stay separate or this recurs.                        |
| `diag/bank_vs_econ`            | Mean terminal bank, scripted-opponent seats only.                                                                                                                                                | Same as `diag/bank_mean`.                                                                                                                                                                                 | Rises while `objective/win_rate_vs_econ` and `objective/margin_vs_econ` stay flat or negative — the farm is producing more without converting it into winning the match.                                                                                                                                     |
| `diag/margin_mean_mirror`      | Mean `final_margin` in self-play.                                                                                                                                                                | By construction ≈ 0 for any policy: each episode contributes `final_margin` and `-final_margin` from its two seats, and both seats are in the mirror population, so the pair cancels. Not a skill signal. | Stays persistently nonzero rather than noisy around 0 — a data-plumbing bug (seats mismatched, or a sign flipped), not a skill gap.                                                                                                                                                                          |
| `diag/mean_sale_price_vs_econ` | Coins per unit actually realised on sale, scripted-opponent seats.                                                                                                                               | `>= 0`, near the market's fair-price scale.                                                                                                                                                               | Rises while `diag/sales_vs_econ` collapses (selling less to cherry-pick price) without `objective/margin_vs_econ` improving — corpus mining found winners take +3.3% here at _flat_ volume, so a price rise bought by simply selling less is the confound `diag/sales_vs_econ` is logged beside it to catch. |
| `diag/realisation_vs_econ`     | Realised price over the market book, `1.0` = par.                                                                                                                                                | Typically near `1.0`; deviations show under/over-realisation vs. the book.                                                                                                                                | Sits well below `1.0` for hundreds of updates without `diag/mean_sale_price_vs_econ` or `objective/margin_vs_econ` moving — chronic mis-execution relative to the book price actually available.                                                                                                             |
| `diag/sales_vs_econ`           | Completed clears per episode, scripted-opponent seats.                                                                                                                                           | `>= 0`, bounded by production capacity over 719 turns.                                                                                                                                                    | Falls to near 0 while `diag/mean_sale_price_vs_econ` rises — selling less to cherry-pick price rather than actually improving execution.                                                                                                                                                                     |
| `diag/units_sold_vs_econ`      | Units moved by those clears, scripted-opponent seats.                                                                                                                                            | `>= 0`.                                                                                                                                                                                                   | Decouples from `diag/sales_vs_econ` (few clears moving very many, or very few, units) — the size distribution of trades shifted independent of trade frequency.                                                                                                                                              |
| `diag/bought_vs_econ`          | Units purchased, scripted-opponent seats.                                                                                                                                                        | `>= 0`.                                                                                                                                                                                                   | Rises sharply with `diag/gross_purchases` while `diag/bank_vs_econ` or `objective/margin_vs_econ` do not move — spend that never converts into sold production or banked coin.                                                                                                                               |
| `diag/final_capital_vs_econ`   | Producing animals owned at the horizon, scripted-opponent seats.                                                                                                                                 | `>= 0`, bounded by farm capacity.                                                                                                                                                                         | Falls together with `diag/bank_vs_econ` while `objective/margin_vs_econ` improves — the pre-registered read that the absolute (capital) reward term is too weak.                                                                                                                                             |
| `diag/mean_sale_price_mirror`  | Same as `diag/mean_sale_price_vs_econ`, self-play seats.                                                                                                                                         | Same.                                                                                                                                                                                                     | Same, with the added caveat that self-play prices are not directly comparable to `diag/mean_sale_price_vs_econ` — both sides are the same policy.                                                                                                                                                            |
| `diag/realisation_mirror`      | Same as `diag/realisation_vs_econ`, self-play seats.                                                                                                                                             | Same.                                                                                                                                                                                                     | Same, with the same self-play comparability caveat.                                                                                                                                                                                                                                                          |
| `diag/sales_mirror`            | Same as `diag/sales_vs_econ`, self-play seats.                                                                                                                                                   | Same.                                                                                                                                                                                                     | Same, with the same self-play comparability caveat.                                                                                                                                                                                                                                                          |
| `diag/units_sold_mirror`       | Same as `diag/units_sold_vs_econ`, self-play seats.                                                                                                                                              | Same.                                                                                                                                                                                                     | Same, with the same self-play comparability caveat.                                                                                                                                                                                                                                                          |
| `diag/bought_mirror`           | Same as `diag/bought_vs_econ`, self-play seats.                                                                                                                                                  | Same.                                                                                                                                                                                                     | Same, with the same self-play comparability caveat.                                                                                                                                                                                                                                                          |
| `diag/final_capital_mirror`    | Same as `diag/final_capital_vs_econ`, self-play seats.                                                                                                                                           | Same.                                                                                                                                                                                                     | Same, with the same self-play comparability caveat.                                                                                                                                                                                                                                                          |
| `diag/mirror_decisive_rate`    | `2x` the raw self-play decisive rate (`final_margin > 0`). Self-play records both seats and exactly one wins, so the raw rate is `0.5` by construction; doubling rescales it to a real 0–1 read. | `[0, 1]`. `1.0` means every self-play game was decisive; it says nothing about the _quality_ of play.                                                                                                     | Reaches 1.0 regardless of whether play is any good — this is the metric from the incident. It rose 0.25 → 0.50 (raw) purely from the policy no longer tying with itself, then pinned at ceiling for 300+ updates while `objective/win_rate_vs_econ` stayed at 0.000.                                         |
| `diag/vtrace_pg`               | V-trace policy-gradient loss term, one component of the total loss actually optimized.                                                                                                           | Real-valued, sign follows the advantage convention; not bounded.                                                                                                                                          | Falls steadily or diverges while `objective/win_rate_vs_econ` does not move — a loss term moving is watched for training stability, not read as capability.                                                                                                                                                  |
| `diag/upgo_pg`                 | UPGO policy-gradient loss term.                                                                                                                                                                  | Same category as `diag/vtrace_pg`.                                                                                                                                                                        | Same as `diag/vtrace_pg`.                                                                                                                                                                                                                                                                                    |
| `diag/entropy`                 | Negative-entropy loss term (positive entropy negated, so it adds to the total as a cost).                                                                                                        | Bounded below by the action space size; falls as the policy sharpens.                                                                                                                                     | Falls to near its floor early and stays there — the policy has collapsed onto very few actions, which reads as "fast, confident progress" from this number alone but is reduced exploration.                                                                                                                 |
| `diag/teacher_kl`              | Teacher KL loss term, zero unless `--teacher` is set.                                                                                                                                            | `>= 0`; `0` when there is no teacher.                                                                                                                                                                     | Nonzero on an arm run without `--teacher`, or zero on one run with it — the teacher flag is not wired to the loss as expected.                                                                                                                                                                               |
| `diag/total_loss`              | Sum of every loss term actually optimized this round.                                                                                                                                            | Real-valued; expected to stay in a modest range under `CLIP_GRADS`.                                                                                                                                       | Diverges (this project has measured a run reach 6e20 within two updates without gradient clipping) — a training instability, not faster learning.                                                                                                                                                            |
| `diag/illegal`                 | Stored action indices the stored mask forbade.                                                                                                                                                   | Nonnegative int; the only acceptable value is exactly `0`.                                                                                                                                                | Nonzero at all — the rollout's sampling or storage is broken. Unlike every other `diag/` metric, this one has no acceptable trend, only a pass/fail read.                                                                                                                                                    |
| `diag/gross_purchases`         | Gross coins spent buying, mean per episode.                                                                                                                                                      | `>= 0`.                                                                                                                                                                                                   | Rises alongside `proxy/money_term` while `diag/bank_mean` stays flat — the money-pump signature, hit three times on this project.                                                                                                                                                                            |

## Consuming this file

`toad.METRIC_PREFIXES` and `toad.METRIC_DEFINITIONS` are the
source of truth this table transcribes; `test_every_logged_metric_carries_a_role_prefix`
in `tests/learn/test_toad_runner.py` pins that `_record` returns exactly the
keys `METRIC_DEFINITIONS` has one-line entries for, and that every one of them
carries a role prefix. This file is not re-checked against that test
automatically, so a future metric rename should update both in the same
commit.
